# Omni Studio 本地工作台

## 使用

双击仓库根目录的 `启动工作台.command`。也可以在项目目录运行 `.venv/bin/omni-vlog studio`，浏览器将打开 `http://127.0.0.1:8765`。关闭终端会停止服务；关闭网页不会。

1. 写下画面、动作与镜头想法。参考图可不选，也可上传最多 5 张 JPG / PNG / WebP。图片作为起始画面时选 1 张。
2. 选择时长和横竖屏，默认 4 秒、360p。清晰度在“更多设置”里。
3. 点击“生成视频”。每次只提交一次生成，不自动重拍。等待期间显示真实阶段，不编造百分比。
4. 预览结果，填写“想改哪里”后点击“修改视频”。修改生成一个新版本，可回到任意旧版本再修改。
5. 点击“下载视频”保存选中的版本。无需经过机器评分批准。

旧作品在“最近创作”中，创意文本和选项草稿保存在浏览器本地。刷新后上传控件需重新选图；已提交作品的参考图和版本都保存在服务器本机。工作台不会自动导入或改动之前的 CLI 任务。

## 调用与恢复

- 不额外调用 Director / Critic / 图片审查模型。模型可能直接拒绝内容或素材；本地图片检查不等于 AI 审查。
- 每个版本有独立的原 provider/project/model/location 绑定及一次视频调用预算。原始版本不会被覆盖。
- 图片会在本机检查格式和大小、纠正方向、去除 EXIF，并缩至最长边 2048；每张最大 10 MB。生成时会将创意和处理后的图片发送到模型。
- 未知结果不会自动重发。获得服务端编号后只做 GET 恢复；进度查询不创建新视频。初次提交自动轮询最多 20 次；保持作品页打开时，每 30 秒继续查询。临时网络或代理故障会保留待处理状态并继续查询，也可点击“立即查询”。
- 创建请求包含幂等编号；同一次前端请求因响应丢失而重试不会重复提交生成。刷新页面后应先查看最近创作，避免主动另建同样的任务。
- 修改能力使用本机已有的 capability 记录；当前 Vertex 已经过真实 edit 验证。未验证的 provider 会给出提示，而非切换模型。
- 工作台默认监听 `127.0.0.1`，仅本机访问，检查请求来源。密钥不返回浏览器；不提供公网部署或账户系统。
- 当前网页聚焦 3–10 秒生成与修改。长视频续写、自动规划/审片等高级流程仍使用 CLI。

## 开发与构建

```bash
uv pip install -e '.[dev]'
npm --prefix ui ci
npm --prefix ui run build
.venv/bin/omni-vlog studio --no-open
```

React + Vite 源码在 `ui/src`。构建产物在 Python 包的 `studio/static` 内，可随 wheel 分发，普通使用无需启动 Node 服务。修改前端后重新构建并刷新网页。可用 `--port 8767` 避开已占用端口。
